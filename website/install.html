1 · GitHub access

Connect your repositories.

  1. Create a classic GitHub personal access token with repo and read:project scopes.
  2. Paste it into Forge’s initial setup and save it. To replace it later, use the gear in the expanded repository sidebar, then Global configuration → GitHub → Save token.

The token enables repository, pull request, issue, and workflow access. Forge stores it locally using encrypted secure storage and requires secure storage to be available before saving it.

2 · OpenAI authentication

Sign in to Codex with ChatGPT.

Codex needs its own OpenAI authentication, separate from your GitHub token. Use a ChatGPT account with access to Codex.

  1. Install the official Codex CLI on your Mac. Forge uses it to run conversations: 
    brew install --cask codex
    Other installation methods are in the official Codex CLI guide.
  2. Open Global configuration → Codex. Leave Executable path blank for automatic discovery, or enter an absolute path to codex. Save a changed path, then click Refresh.
  3. Click Sign in with ChatGPT and finish the OpenAI sign-in in your browser. Return to Forge and confirm the account shows Signed in.

Forge keeps its local Codex sign-in in a separate Codex home. Complete this sign-in in Forge even if you already use Codex in another app. To use a different account for one project, open Project configuration → Codex overrides and enable Use a separate Codex account for this project.

ChatGPT access is governed by your account and workspace permissions. See OpenAI’s authentication guide for browser and device sign-in details.

3 · Your first project

Choose a Git checkout.

  1. Select a repository and open the gear beside the project’s name.
  2. Under Checkouts, choose its local Git folder and confirm the checkout check succeeds.
  3. Open Codex with ⌘⇧C and create a thread. Choose its environment and starting branch or worktree before sending your first prompt.

New threads use an isolated worktree by default. You can also start on the default branch, a new named branch, or the current branch. Your conversations, drafts, and project configuration stay on your computer.

Optional · Remote development

Run Codex on your own SSH host.

Forge connects to a Linux or macOS development machine over SSH. Codex and project tools run there, using that host’s Codex account and Git checkout.

Prepare the remote host

  1. Install a compatible Codex CLI, Git, and your project’s build tools as the development user. Clone or prepare a writable Git checkout with at least one commit.
  2. Set up SSH keys or an agent and connect once from your Mac to confirm the host key: 
    ssh devbox
    Replace devbox with your SSH alias or user@hostname. Configure keys and ports in ~/.ssh/config. Forge requires non-interactive SSH authentication and a known host key.
  3. In that SSH session, authenticate Codex as the same development user: 
    codex login --device-auth
codex login status
    Open the displayed link in your browser and enter the one-time code. Device code login may need to be enabled in your ChatGPT account or workspace permissions; see the headless sign-in guide.
  4. Prepare and start the managed app-server daemon on the remote host: 
    codex app-server daemon bootstrap
codex app-server daemon start
    The remote CLI must support daemon/proxy connections and command/exec. Verify the daemon remains running after SSH logout; a headless Linux user service may need administrator-enabled lingering.

Connect it in Forge

  1. Open Global configuration → Environments → Add environment…. Set a name, SSH host, and Remote Codex executable (codex or its absolute path on the host).
  2. Edits save automatically. Wait for the green connection check, or click the status icon beside the host to retry. Failed checks include a setup procedure.
  3. Open Project configuration → Checkouts and enter that environment’s Git checkout path on the remote host. Wait for the checkout check to pass. Optionally choose it as the project’s Default environment.
  4. Create a new thread and select the remote environment before starting it. Started threads retain their environment and account selection.

Forge connects to the existing daemon; it does not install or start it for you. Keep the host awake and reachable. Remote Codex sign-in stays on that host. Remote terminals use SSH login shells; reconnecting after a disconnect starts a fresh shell.

If the connection drops, use Reconnect on the interrupted or failed thread. Local Finder/editor actions, diff and merge tools, and attachments are unavailable for remote threads. See the remote workspace guide for detailed behavior.
